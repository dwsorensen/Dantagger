Inside the FPGA

The FPGA has two jobs. While idle it is a controller: it sets trigger levels, configures the TDC chip and calibrates the link to it. While streaming it is a pipe: it catches every result the TDC chip sends, stamps it with a clock, queues it, and pushes it to the PC in 4 KiB frames.

5 359 lines of SystemVerilog in 12 modules (TDC_Firmware/project_1/rtl/), running in five clock domains. Hardware safety came first in every trade-off: every new FPGA output drives a chip input only, and the clock to the TDC chip stays switched off until the host turns it on.

Two modes

Controller when idle, pipe when streaming

Configuration mode (the default)

The PC sends one command at a time in a 4 KiB frame. The FPGA checks it, carries it out, and answers with a 4 KiB response. The response also reports the board's whole state: trigger levels read back, the GPX2 registers, link counters, temperature, and the last run's counts.

The commands set trigger levels and hysteresis, configure, initialise and reset the GPX2, set the LVDS sampling point (LVDS_SET, LVDS_PHASE), and count test-pattern frames (LINK_TEST). The full list is on Bits on the wire.

Streaming mode

After START, the FPGA sends DATA frames until STOP arrives or a set time window ends. While it streams it answers only STATUS and STOP. Every other command gets BUSY and does nothing. That is why changing a trigger level during a measurement means stopping, applying and restarting.

START is refused (NOT_READY) unless the GPX2 is measuring with a verified configuration, LCLKIN is on, and the LVDS clocks are locked. A compact START also needs a 12- to 24-bit reference index and at most 18 stop bits.

The life of one command
  1. Receive. tdc_engine reads a 4096-byte COMMAND frame from the FT601.
  2. Check. It checks the magic, version, CRC, zero padding and the GPX2 board rules. A bad frame is dropped silently and counted.
  3. Hand over. Over a four-phase handshake (req, copy, ack), the engine passes the opcode and arguments to sys_ctrl in the 100 MHz domain.
  4. Do it. sys_ctrl runs board_ctrl, gpx_ctrl or an lvds_rx request: SPI, I²C, phase steps or a link test.
  5. Snapshot. It copies the run counters and board results while nothing is changing them.
  6. Respond. The engine builds the RESPONSE: 113 fields, the transaction ID echoed, and a CRC.

Fields cross between clock domains only while they are held stable. The other domain copies them two or three cycles after it sees req, and the result words change only between that copy and ack. A request that is not acknowledged in time is abandoned and flagged (field 58 bit 10).

Catching bits

Finding the right moment to sample

The FPGA makes the GPX2's clock, and the data comes back after an unknown delay through the chip and the cables. At 250 MHz DDR a bit lasts only 2 ns, and near each bit edge the value is unreliable. Calibration slides the sampling instant across the bit while the GPX2 sends a known test pattern, and settles in the middle of the widest error-free stretch.

The sampling instant within a bit is (bit phase mod N) × 2 ns + phase step × 17.857 ps. N is the number of 2 ns samples per bit: 1 at 250 MHz DDR, 16 at 31.25 MHz SDR. Each point of the sweep runs a LINK_TEST. A point is good only if every lane decoded frames with the right pattern and no structure errors. The real board (2026-10-22) calibrated at 250 MHz DDR at phase step 31, with 0 wrong events in about 117 M test-pattern events afterwards.
This model puts a ±225 ps uncertain zone around each data edge and a random delay per board. The real procedure is tdcctl::Session::calibrate. It configures the GPX2 with LVDS_TEST_PATTERN = 1 (reference index 0xF0CCAA, stop 0x0AACF0, truncated to the widths) and sweeps every bit phase with phase steps of max(1, N·112/100). It picks the centre of the widest circular run of good points, runs a 10× longer final link test there, and restores the real configuration. The result goes into the state file (~/.local/state/dantagger/<serial>.release2.json), so later opens skip calibration until the next power cycle.
Reading a message

The frame decoder

Each channel has two lanes. SDO carries the bits. FRAME is high for the first 8 bits of each message, so a rising FRAME marks a start. After 42 bits the decoder has one event: a 24-bit reference index and an 18-bit stop result. Edit the values, or add a glitch on FRAME.

FRAME highreference index bitsstop result bitsstructure errorDashed lines: the 4-bit words the decoder takes per 8 ns cycle
gpx_deser.sv evaluates the four bits of a word in parallel. Within a word a frame either continues from the last word, where its position is known, or starts in this word. A frame that starts in a word is at most 3 bits old, so FRAME must still be high and it cannot complete there (frames have at least 14 bits). At most one frame completes per word. The result is checked against a bit-serial reference decoder (tb_gpx_deser: 72 streams, 17 137 frames, 19 607 structure errors, widths 14–44).
The event queue

Four channels, one queue, a USB link that sometimes pauses

Each channel's newest event waits in a holding register until the arbiter writes it into the queue, one record per 8 ns cycle. The queue drains to USB. Push the rates past what the link carries, or pause the PC, and watch the queue fill, events drop, and OVERFLOW markers record the losses.

The arbiter's priority is START, then OVERFLOW (if any events were dropped), then TIME (when the coarse clock's low 14 bits wrap), then the holding registers with channel 1 first, then END. An event is dropped when it waits more than 8 cycles, or when its channel's next event arrives while the register is still full. Markers wait for space and are never dropped. So the first record after the queue has been full is a marker with the full 48-bit coarse time.
This simulates every 8 ns cycle. Arrivals per channel are random, but never closer than one 84 ns GPX2 message, as on the real link. The real pipeline is lvds_rx.sv (arbiter in its always_comb, HOLD_LIMIT = 8, TIME_MARK_BITS = 14) feeding an XPM async FIFO (first-word-fall-through, write 125 MHz, read 66.67 MHz). The link rate here is a steady average. The real FT601 moves 4 KiB frames in bursts and needs 16 idle cycles after each DATA frame (128 after every 8th). The compact rate is an estimate: twice the measured 64-bit rate, less a TIME marker (3 words) every 131 µs and the EPOCH words.
Out to USB

Building DATA frames

tdc_engine reads records out of the queue and builds 4 KiB DATA frames in block RAM, one 32-bit word per FT clock, computing the CRC as it goes. Two DATA frame slots and one RESPONSE slot share the RAM, so one frame can be filled while another is sent.

A frame starts when a full frame's worth is waiting (503 records, or 1007 compact words), when records have waited 1 ms, or at once while the run ends. STOP drains everything already captured, and its response follows the last DATA frame.

Compact packing. Each record leaving the queue becomes one 32-bit word (an event), or two (an event whose index bits 23:12 changed: EPOCH first), or three (a marker: HEAD, HI, LO). A record never straddles two frames, and PAD words fill the rest of a frame. An event whose stop result would look like a marker word (bits 17:12 all ones, ≥ 258 048: impossible with 125 000 divisions unless the link is corrupt) is dropped and counted in field 111.

Bus etiquette. These rules are carried over unchanged from the Test_project engines that ran on hardware. One ownership register; a grant only after idle cycles; RD_N only after OE_N has been low for a cycle; WR_N only after the FPGA has driven the bus for a cycle; every FT601-facing pin an IOB register. No frame starts while TXE_N is high, and released cycles follow DATA frames so a waiting STOP is always read.

Safety and proof

Why it should not hurt the board

  • Every new FPGA output drives a chip input only. The only two-way pins are the FT601 bus (proven in earlier projects) and open-drain I²C, which can only pull low or let go.
  • LCLKIN, the clock to the GPX2, is high-impedance from power-up until the host enables it, and goes off again after each stream or link test.
  • DISABLE and RSTIDX are tied low, the same level as the board's pull-downs. The GPX2 chip select starts high.
  • The bus supervisor releases the FT601 bus only while the FT clock is measured at 66.67 MHz and the MMCM is locked.
  • Simulation: the full top-level bench passes (185 responses, 86 DATA frames, 33 compact) with the Xilinx ISERDES model.
  • Mutation campaign: 67 deliberate bugs put into the RTL, and every non-equivalent one caught by a testbench failure.
  • Cross-check: the host's decoder reads all 271 frames the RTL produced, and its software packer reproduces the compact frames word for word.
  • Hardware: release 2 ran on the board on 2026-10-22. Release 3 has not been loaded yet.
